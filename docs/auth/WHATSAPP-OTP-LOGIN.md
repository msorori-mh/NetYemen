# الدخول برقم الجوال عبر واتساب (WhatsApp OTP)

## كيف يعمل

1. العميل يكتب رقم جواله اليمني (`77XXXXXXX` ويُحوَّل إلى `+9677XXXXXXXX`).
2. التطبيق يستدعي `signInWithOtp(phone, channel: whatsapp)`؛ Supabase Auth يرسل رمزاً
   من 6 أرقام في محادثة واتساب على الرقم نفسه.
3. العميل يُدخل الرمز في شاشة التحقق؛ يُتحقَّق منه كـ OTP هاتف (`type: sms`).
4. أول دخول برقم جديد يُنشئ الحساب تلقائياً (المشغّل `handle_new_user` يُنشئ الملف
   والدور)، ثم تأتي بوابة الرمز السري (PIN) كالمعتاد.

الكود: `lib/features/auth/data/customer_auth_repository.dart`،
`lib/features/auth/presentation/login_screen.dart`، `otp_screen.dart`.

الدخول بحساب Google ما زال متاحاً، والدخول بكلمة المرور لحسابات المختبرين
(`test-onboarding`) مخفي خلف زر «حسابات المختبرين».

## مرحلة الاختبار: عشرة أرقام برمز ثابت `123456`

إلى أن يُحدَّد مزوّد واتساب، تُضبط في Supabase **أرقام اختبار** لا تُرسل لها أي رسالة،
ويُقبل لها الرمز الثابت `123456`.

في لوحة Supabase: **Authentication → Sign In / Providers → Phone**

1. فعّل **Enable Phone provider**.
2. اختر مزوّد الرسائل **Twilio** (أو Twilio Verify). إلى أن يتوفر حساب حقيقي يمكن
   ملء الحقول بقيم مؤقتة؛ أرقام الاختبار لا تمر عبر المزوّد، والأرقام الأخرى ستفشل
   في الإرسال (وهذا متوقع في هذه المرحلة).
3. في **Test Phone Numbers and OTPs** أضف الأرقام العشرة بالصيغة الدولية بلا `+`،
   مفصولة بفواصل:

   ```text
   9677XXXXXXXX=123456, 9677YYYYYYYY=123456, ...
   ```

4. اضبط **Test OTPs Valid Until** على تاريخ نهاية مرحلة الاختبار (لا تتركه مفتوحاً).
5. احفظ، ثم جرّب من التطبيق: أدخل أحد الأرقام → «إرسال رمز التحقق عبر واتساب» →
   أدخل `123456`.

| # | رقم الاختبار (يُعبّأ لاحقاً) | الرمز |
|---|---|---|
| 1 | | 123456 |
| 2 | | 123456 |
| 3 | | 123456 |
| 4 | | 123456 |
| 5 | | 123456 |
| 6 | | 123456 |
| 7 | | 123456 |
| 8 | | 123456 |
| 9 | | 123456 |
| 10 | | 123456 |

**تحذير أمني:** من يعرف رقم اختبار يستطيع الدخول إلى ذلك الحساب بالرمز `123456`.

- استخدم أرقاماً يملكها فريق الاختبار فقط، ولا تضف رقم عميل حقيقي أبداً.
- لا تودِع رصيداً حقيقياً في محافظ هذه الحسابات.
- عند الإطلاق: احذف كل أرقام الاختبار (جدول الإعدادات في
  `docs/OPERATIONS-RUNBOOK.md` §9 يشترط «لا أرقام اختبار»).

للتطوير المحلي، الأرقام في `supabase/config.toml` تحت `[auth.sms.test_otp]`
(محلي فقط، لا تُدفع إلى المشروع المستضاف).

## عند اختيار مزوّد واتساب

Supabase يدعم قناة WhatsApp مع **Twilio** و **Twilio Verify** فقط.

- **Twilio Verify** (الأسهل): أنشئ Verify Service وفعّل قناة WhatsApp فيه؛ Twilio يتكفّل
  بقالب رسالة المصادقة. في Supabase اختر *Twilio Verify* وأدخل Account SID و
  Auth Token و Verify Service SID.
- **Twilio Programmable Messaging**: يحتاج رقم مرسِل واتساب معتمداً (WhatsApp Business)
  وقالب مصادقة موافَقاً عليه من Meta.

بعدها:

- احذف أرقام الاختبار أو قلّصها، واترك **Test OTPs Valid Until** في الماضي.
- راجع حدود الإرسال (افتراضياً طلب رمز واحد كل 60 ثانية لكل رقم، وصلاحية الرمز ساعة)
  وفعّل CAPTCHA إن ظهرت محاولات إغراق، لأن كل رسالة لها تكلفة.
- جرّب رقماً حقيقياً من شبكة يمنية والتأكد من وصول الرسالة.

## ما بعد الدخول

الدخول بالرمز يثبت ملكية الرقم فقط. حماية المال منفصلة: الشراء وكشف الكرت وواصل ون
تتطلب **رمز PIN** يتحقق منه الخادم في الجلسة نفسها خلال 15 دقيقة
(`require_recent_account_pin`). التطبيق يطلب الرمز عند الحاجة.
